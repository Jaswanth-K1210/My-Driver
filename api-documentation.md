# MyDriver API

The MyDriver backend serves the customer website, the operations console and both mobile apps.
It is a Fastify + TypeScript service in `prototype/backend`.

- **Base URL:** `http://localhost:4000` in development. In production it is `https://api.mydriver.in` (`API_DOMAIN`).
- **Format:** JSON request and response bodies. Fields are snake_case, times are ISO 8601, and amounts are rupees as numbers.
- **Validation:** every request is checked against a Zod schema. Unknown fields are rejected wherever a schema is `.strict()`.
- **Client:** the apps call the API through `prototype/shared/api-client.js`, which handles tokens and refresh. Use it rather than calling `fetch` directly.

## Authentication

| Who | How to sign in | Endpoint |
|---|---|---|
| Customers and drivers | Phone OTP: request a code, then verify it | `POST /v1/auth/otp/request`, `POST /v1/auth/otp/verify` |
| Customers and drivers | Google ID token | `POST /v1/auth/google` |
| Staff | Email + password, **only from the console origin** (`ADMIN_WEB_URL`) | `POST /v1/auth/staff/login` |

Every sign-in returns an `access_token` (a short-lived JWT) and a `refresh_token`.

- Send the access token as `Authorization: Bearer <access_token>`.
- When a request returns `401`, exchange the refresh token for a new pair with `POST /v1/auth/refresh`.
- `POST /v1/auth/logout` revokes the refresh token.

Checking a token never touches the database. The role is inside the JWT.

**Roles:** `CUSTOMER`, `DRIVER`, `SAFETY_DESK_AGENT`, `OPS_MANAGER`, `FINANCE`, `SUPER_ADMIN`.
Signing in can only ever create the `CUSTOMER` and `DRIVER` roles. Staff roles are granted with
`npm run grant-role` or `npm run seed:staff`.

**Origins:** `/v1/admin/*` refuses requests from the customer website's origin, and staff sign-in
only works from the console origin.

## Errors

Every error uses the same shape:

```json
{ "error": { "code": "TRIP_NOT_FOUND", "message": "No such trip", "details": {} } }
```

| Status | Meaning |
|---|---|
| 400 | `VALIDATION_FAILED`. `details` lists each failing `path` and `message` |
| 401 | `UNAUTHENTICATED`: missing or expired token. Refresh it and retry |
| 403 | `FORBIDDEN_ROLE`, or the request came from the wrong origin |
| 404 | The resource does not exist, or you are not allowed to know that it does |
| 409 | State conflict, e.g. the trip has already moved past this step |
| 429 | `RATE_LIMITED`. OTP requests and place search have per-user and per-phone quotas |

## Payments flow

1. `POST /v1/trips/book` creates the trip and a payment order. Dispatch waits for the hold.
2. The customer opens `GET /v1/payments/:id/checkout` (a hosted Razorpay page) and authorises the fare.
3. Razorpay calls the signed webhook. The payment becomes `AUTHORIZED` and dispatch starts.
4. On completion the backend captures the lower of the final fare and the hold. Any overage is recorded as
   `amount_due`. Cancelling, or no driver being found, releases the hold.

## Realtime (WebSocket)

1. `POST /v1/realtime/ticket` returns a single-use ticket that expires after a few seconds.
2. Connect to `ws(s)://<api>/v1/integrity?ticket=<ticket>`.
3. Send `{ "type": "SUBSCRIBE", "trip_id": "…" }` for a trip you are a participant in.

| Direction | Frame `type` | Purpose |
|---|---|---|
| client → server | `SUBSCRIBE`, `UNSUBSCRIBE` | Start or stop receiving a trip's events |
| client → server | `DRIVER_TELEMETRY` / `CUSTOMER_TELEMETRY` | Position (and driver motion sensors) during `HANDSHAKE_PENDING` / `IN_TRIP` |
| client → server | `PONG` | Reply to `PING` |
| server → client | `SUBSCRIBED`, `UNSUBSCRIBED` | Acknowledgements |
| server → client | `TRIP_OFFER` | New offer for an online driver |
| server → client | `TRIP_STATE_CHANGED` | The trip moved to a new status |
| server → client | `DRIVER_LOCATION` | Live driver position for the customer's map |
| server → client | `ANOMALY_TRIGGERED` | Speed, route or telemetry warning raised |
| server → client | `PING`, `ERROR` | Keep-alive; `{ code, message }` on a bad frame |

The full frame schemas are in `prototype/backend/src/realtime/protocol.ts`.

## Other endpoints

- `GET /health`: liveness. `GET /ready`: checks that the database and Redis are reachable.
- `GET /metrics`: Prometheus metrics, protected by `METRICS_TOKEN` in production.
- `POST /v1/payments/webhook`: Razorpay only. It verifies the signature and is idempotent on the event id.
